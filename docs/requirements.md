# 需求規格

## 1. 目的與範圍

Bubble Sort Visualizer 是一個在瀏覽器執行的排序演算法教學工具。v1 只能逐步顯示 2–10 個數字的氣泡排序；v2 以氣泡排序為主角，擴充成十種排序演算法，讓學生能控制播放、對照虛擬碼、觀察成本，並比較不同演算法在不同資料上的表現。

主要使用者：

- **學生**：修資料結構或演算法課程，想看懂排序每一步在做什麼。
- **老師／助教**：上課示範，或把特定例子分享給學生。

## 3. 使用者故事與驗收條件

### US-01 逐步播放

身為學生，我想要播放、暫停並一步一步前進或後退，才能依自己的速度看懂每一步。

- 按「播放」或空白鍵開始自動播放；再按一次暫停。
- 「下一步」（→）每次只套用一個事件；「上一步」（←）回到前一個狀態，畫面、虛擬碼標示與統計數字都與當時一致。
- 「回到開頭」（Home）恢復原始資料；「跳到結果」（End）直接顯示排序完成的陣列。
- 速度可在每秒 0.5–800 步之間調整，播放中調整立即生效。
- 播放到最後自動停止；在結尾按播放會從頭開始。

### US-02 時間軸

身為學生，我想要拖曳時間軸跳到任何一步，才能快速回到有疑問的地方。

- 時間軸範圍是 0 到總步數，拖曳後畫面立即對應該步。
- 旁邊顯示「第 k / N 步」。

### US-03 選擇演算法

身為學生，我想要在十種排序演算法之間切換，才能比較它們的做法。

- 可選：氣泡、雞尾酒、選擇、插入、希爾、合併、快速、堆積、計數、基數排序；預設為氣泡排序。
- 切換演算法時保留目前資料並回到第 0 步。
- `[`、`]` 可切換到上一個／下一個演算法。

### US-04 虛擬碼對照

身為學生，我想要看到目前執行的是虛擬碼哪一行，才能把動畫和程式對起來。

- 每個演算法都有虛擬碼；每一步都標示對應的行。
- 標示的行會自動捲到可見範圍，但不捲動整個頁面。

### US-05 每一步的文字說明

身為學生，我想要看到每一步的文字說明，才能知道顏色變化代表什麼。

- 比較時顯示兩個位置、兩個值與比較結果，例如「比較 A[3] = 11 與 A[4] = 8：11 > 8」。
- 交換、寫入、樞紐、計數、分桶、標記就定位等事件都有對應說明。
- 暫停或逐步操作時，說明會透過 `aria-live` 讓螢幕閱讀器朗讀；快速播放時不朗讀。

### US-06 即時統計

身為學生，我想要看到比較、交換、寫入次數與排序進度，才能感受不同演算法的成本。

- 顯示步驟、比較、交換、寫入、輔助陣列寫入、額外空間。
- 顯示「剩餘逆序對」與排序進度（已消除的逆序對比例）。
- 氣泡排序與插入排序的交換次數等於初始逆序對數。

### US-07 演算法資訊

身為學生，我想要看到每個演算法的複雜度與性質，才能準備考試並解釋觀察到的現象。

- 顯示最佳、平均、最差時間複雜度與空間複雜度。
- 顯示是否穩定、原地、自適應、比較式；滑鼠停留時說明名詞。
- 每個演算法都有一句「觀察重點」，引導學生用這個工具驗證性質。

### US-08 資料量與初始排列

身為學生，我想要調整資料量並選擇初始排列，才能看到輸入形狀對演算法的影響。

- 資料量 5–100。
- 初始排列：隨機、已排序、反向、幾乎排序、少數不同值。
- 「重新產生」（N）用新的亂數種子產生同類型資料。
- 同一個種子永遠產生相同資料，比較模式中各演算法使用完全相同的輸入。

### US-09 自訂資料與錯誤訊息

身為學生，我想要輸入自己的數字，才能重現課本或作業中的例子。

- 接受 2–100 個 0–999 的整數，可用逗號、頓號、分號、空白或換行分隔，全形數字與全形逗號也接受。
- 不合法時不改變目前資料，並指出第一個問題的位置與原因，例如「第 2 個值「a」不是整數。」、「第 4 個值「1200」超出範圍，請輸入 0–999 的整數。」。
- 合法時顯示「已套用 n 個數字」，並把輸入整理成標準格式。

### US-10 比較模式

身為學生，我想要讓多個演算法排序同一組資料，才能直接比較誰比較快。

- 可勾選 2–10 個演算法；少於 2 個時顯示錯誤並保留原本的選擇。
- 所有演算法共用一個「操作時鐘」：每次比較、交換或寫入算 1 次操作，大家以相同速度前進。
- 每條跑道顯示長條圖、進度、操作數；完成時顯示名次。
- 全部完成後顯示結果表（比較、交換、寫入、總操作）。
- 播放、逐步、倒退、時間軸與速度控制都可使用。

### US-11 預測模式

身為學生，我想要在看到答案前先預測，才能檢查自己是否真的懂。

- 適用於「每次比較後決定是否交換這一對元素」的演算法：氣泡、雞尾酒、插入、希爾排序；其他演算法的開關停用並說明原因。
- 開啟後，播放或逐步走到「比較」時暫停，詢問「會交換嗎？」，此時說明文字不顯示比較結果。
- 作答後顯示對錯、理由與累計分數；按「繼續」接著執行。
- 倒退再前進時，同一步不會重複出題。

### US-12 分享連結

身為老師，我想要把目前的例子做成連結，才能讓學生打開就看到同一組資料。

- 連結包含模式、演算法、資料（預設排列＋資料量＋種子，或自訂數字）。
- 連結中不合法的參數會被忽略，網站仍以預設值開啟。

### US-13 鍵盤操作

身為習慣鍵盤的使用者，我想要不用滑鼠就能操作。

- 快捷鍵：空白（播放／暫停）、← →、Home、End、↑ ↓（速度）、`[` `]`、N、P、C（切換模式）、M（音效）、?（說明）。
- 在文字欄位輸入時不觸發快捷鍵；焦點在按鈕上時空白鍵只按該按鈕；滑桿保留自己的方向鍵。
- 所有按鈕都有可見的焦點框與文字標籤。

### US-14 語言

身為使用者，我想要在繁體中文與英文之間切換。

- 預設繁體中文；切換後所有文字（含說明、錯誤訊息、演算法介紹）立即更新，選擇會被記住。

### US-15 外觀與裝置

身為使用者，我想要在手機、深色模式與「減少動態效果」設定下都能順利使用。

- 寬度 360px 的手機上沒有水平捲動，控制列自動換行。
- 預設依系統設定使用淺色或深色，可手動切換並記住。
- 系統開啟「減少動態效果」時，長條不做過渡動畫。
- 狀態不只用顏色表示：交換、寫入、比較另有符號（⇄、↓、?），指標與樞紐有文字標籤，並有圖例。

### US-16 音效

身為使用者，我想要選擇是否聽到排序的聲音。

- 音效預設關閉；開啟後，每次比較、交換或寫入發出短音，音高對應數值大小。
- 快速播放時每個畫面最多發出一個音，避免爆音。

## 4. 非功能需求

| 編號 | 項目 | 需求 |
|---|---|---|
| NFR-1 | 部署 | 純靜態網站，沒有建置步驟；GitHub Pages 從 `main` 分支根目錄的 `index.html` 發布 |
| NFR-2 | 相容性 | 支援 ES 模組的現代瀏覽器（Chrome、Edge、Firefox、Safari 最新兩版） |
| NFR-3 | 效能 | 資料量 100 時，切換演算法或資料在一瞬間完成；每秒 800 步播放時畫面仍流暢；任意位置倒退最多重播 64 個事件 |
| NFR-4 | 正確性 | 每個演算法的事件可重播出排序結果；被標記「已就定位」的元素之後不再移動（由單元測試保證） |
| NFR-5 | 可維護性 | 演算法、引擎、介面分層；排序核心不依賴 DOM，可在 Node 測試；公開函式有 JSDoc |
| NFR-6 | 品質流程 | 每次 push 與 pull request 由 GitHub Actions 執行語法檢查與單元測試 |
| NFR-7 | 無障礙 | 鍵盤可操作、焦點可見、狀態有文字與符號、尊重減少動態效果、深淺色對比足夠 |
| NFR-8 | 隱私 | 不追蹤使用者；只在瀏覽器的 localStorage 保存語言、主題、速度等偏好 |

## 5. 限制與假設

- 視覺化的資料是整數；自訂輸入限制為 2–100 個、每個 0–999，確保長條圖在手機上仍看得清楚。演算法本身也能處理負數（由測試涵蓋）。
- 快速排序使用 Lomuto 分割並以最右邊元素為樞紐，刻意保留「已排序資料是最差情況」這個教學重點。
- 計數排序直接依計數重建整數，因此在資訊面板中「穩定」標示為不適用。
