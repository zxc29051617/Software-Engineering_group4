# 測試計畫

## 1. 目標

- 每個排序演算法在各種輸入下都排序正確。
- 演算法送出的事件可信：格式正確、重播得出相同結果，「已就定位」的標記不說謊。
- 播放引擎在任何位置前進、倒退、跳轉都得到一致的狀態。
- 介面邏輯（顏色規則、快捷鍵、分享連結、輸入檢查、翻譯）在沒有瀏覽器的環境下也能驗證。
- 每次 push 與 pull request 自動執行，壞掉的改動不會悄悄進入 `main`。

## 2. 測試層級與工具

| 層級 | 工具 | 內容 | 執行時機 |
|---|---|---|---|
| 靜態檢查 | `npm run check`（`scripts/check.js`） | 對每個 JS 檔執行 `node --check`；確認所有相對路徑 import 與 `index.html` 引用的檔案都存在（避免 GitHub Pages 上 404） | 本機、CI |
| 單元測試 | `npm test`（Node 內建 `node:test`，不需安裝套件） | 演算法、事件、狀態、播放器、比較模式、輸入、翻譯、介面純函式 | 本機、CI |
| 瀏覽器冒煙測試 | Playwright（Chromium，無頭模式） | 開啟網站，檢查主控台錯誤與失敗的請求，操作播放、倒退、切換演算法、自訂輸入、預測模式、語言、比較模式、說明視窗；手機寬度與減少動態效果 | 發布前手動執行 |
| 手動驗收 | 瀏覽器、手機、螢幕閱讀器 | 依第 5 節清單 | 發布前 |

CI：`.github/workflows/test.yml` 在 Node 20、22、24 上執行 `npm run check` 與 `npm test`。

## 3. 測試預言（oracle）

最重要的檢查集中在 `backend/engine/verify.js` 的 `verifyTrace(algorithm, input)`，對一次排序檢查：

1. 每個事件都通過 `validateEvent`（類型已知、行號在虛擬碼範圍內、索引不越界、不和自己比較或交換、輔助陣列已建立……）。
2. 演算法自己的結果等於 `input` 排序後的結果。
3. 從 `input` 重播所有事件，得到與演算法相同的陣列（事件沒有漏掉任何資料變動）。
4. 被 `sorted` 標記的位置，當下的值就等於最終排序結果中該位置的值，而且之後不再被交換或寫入。
5. 結束時每個位置都被標記過。

`test/events.test.js` 另外用四個「故意寫錯」的假演算法確認 verifier 真的抓得到錯誤：偷偷交換不送事件、提早標記已就定位、忘了標記、索引越界。

## 5. 手動驗收清單

- [ ] 桌機 Chrome、Firefox、Safari：播放、暫停、逐步、倒退、時間軸、速度都正常，主控台沒有錯誤。
- [ ] 手機寬度（360–414px）：沒有水平捲動，演算法按鈕可左右滑動，控制列換行後仍可操作。
- [ ] 只用鍵盤完成：選演算法、播放、逐步、開說明視窗（?）並用 Esc 關閉、輸入自訂資料並套用。
- [ ] 螢幕閱讀器（VoiceOver 或 NVDA）：逐步時會唸出說明文字；按鈕都有名稱。
- [ ] 系統設定「減少動態效果」時長條沒有過渡動畫；深色模式下文字與長條對比清楚。
- [ ] 自訂輸入 `5, a, 3`、`1000`、`7` 分別出現對應的錯誤訊息，且原本的資料不變。
- [ ] 預測模式：氣泡排序在比較時暫停出題；選擇排序時開關停用並說明原因。
- [ ] 比較模式：勾選少於 2 個演算法時出現錯誤；全部完成後出現結果表。
- [ ] 分享連結在新分頁開啟後，演算法與資料相同。
- [ ] 音效預設關閉，開啟後有聲音，關閉後安靜。

## 6. 執行方式

```bash
npm run check   # 靜態檢查
npm test        # 單元測試
```

最近一次結果：`npm run check` 通過；`npm test` 共 270 個測試全數通過；Playwright 冒煙測試沒有主控台錯誤或失敗的請求，手機寬度 375px 沒有水平捲動。
